# Yugabyte Meko in 6 shots
Shared memory, knowledge, and decision traces for multi-agent systems, served over MCP.

## Shot 1 · canonical · One agent writes, a different agent recalls
**Input:** Two agents run as separate processes under the same API key and datapack. The reviewer starts later with an empty context.
```json
// planner process
{"tool": "memory_add", "args": {"text": "DECISION: ship the migration behind a flag. REASON: rollback must take under 5 min.",
  "agent_id": "planner", "datapack_id": "<uuid>"}}

// reviewer process
{"tool": "memory_search", "args": {"query": "how are we shipping the migration?",
  "agent_id": "reviewer", "datapack_id": "<uuid>"}}
```
**Output:** The reviewer gets the planner's memory back, ranked by semantic, keyword, and entity match. Calling with `agent_id: "reviewer"` doesn't filter it out, because search spans all of the user's agent namespaces in the datapack.
**Signal:** Memory belongs to the datapack and to the user account behind the API key. `agent_id` labels who wrote what. It isn't a wall between agents.

## Shot 2 · edge · A teammate sees nothing until something promotes it
**Input:** The datapack is shared with user 2. User 2's agent runs the same `memory_search`. Then user 1, the owner, promotes the memory, and user 2 searches again.
```json
{"tool": "memory_promote", "args": {"memory_ids": ["<id>"], "agent_id": "planner", "datapack_id": "<uuid>"}}
```
**Output:**
```
user 2, before promote → results: []
user 1, promote        → moved to the datapack's shared layer (one-way)
user 2, after promote  → results: [ "DECISION: ship the migration behind a flag…" ]
```
**Signal:** Memories are private by default. There are three zones: **private** (your agents), **learnings** (candidates a human reviews in the portal), and **institutional** (Collective Memory and Shared Knowledge, which every member's agents can read). Only an owner or maintainer can promote, and a promotion can't be undone.

## Shot 3 · edge · Two ways to write, and they don't store the same thing
**Input:** The same fact is written two ways.
```json
{"tool": "conversation_add_message", "args": {"conversation_id": "c1", "agent_id": "planner",
  "input": "ok sounds good",
  "output": "Decided: we'll pin Postgres 16 for the migration.", "datapack_id": "<uuid>"}}

{"tool": "memory_add", "args": {"text": "Migration pins Postgres 16.", "agent_id": "planner", "datapack_id": "<uuid>"}}
```
**Output:** `conversation_add_message` stores the whole turn as history and for the trace. An LLM extractor pulls durable facts from it server-side, asynchronously and on a best-effort basis. It works from the user turn, so "Postgres 16" probably never becomes a memory *(unverified: whether assistant output is ever extracted)*. `memory_add` stores your text as written.
**Signal:** Use conversations for the record and `memory_add` for facts you can't lose: decisions the agent made, facts from tool output, and corrections.

## Shot 4 · edge · "Get all" doesn't return everything
**Input:** An agent tries to export its memories.
```json
{"tool": "memory_get_all", "args": {"agent_id": "planner", "datapack_id": "<uuid>"}}
```
**Output:** You get a recent window of about 20 memories plus a total count, and there are no pagination arguments. Older items are reachable only through `memory_search` or `memory_get_by_id`.
**Signal:** Retrieval goes through ranked search, not scans. Build your agent around asking good queries, not around listing everything.

## Shot 5 · real-world · A handoff that carries the why
**Input:** A researcher agent saves its turn with the reasoning and plan attached. A procurement agent, or a human auditor, picks it up a week later.
```json
{"tool": "conversation_add_message", "args": {"conversation_id": "c7", "agent_id": "researcher",
  "input": "Which queue vendor should we use?",
  "output": "Recommend vendor B.",
  "reasoning": "A has the lower list price, but egress fees dominate at 40 TB/month.",
  "plan": ["compare list pricing", "model egress at 40 TB/month", "check SLA terms"],
  "datapack_id": "<uuid>"}}
```
**Output:** The turn shows up as a **decision trace** in the Observe view, linking the prompt, plan, reasoning, and any memories it produced. The next agent inherits *why* vendor B won, not just "B". Recent conversations stay hot in YugabyteDB, and older ones tier to S3 *(unverified: the window, and whether old history is kept in full or only as summaries)*.
**Signal:** A standard trace records which calls ran. A decision trace records why the agent decided what it did. Meko is built around that second kind, because handoffs and audits (for example under the EU AI Act) depend on it.

## Shot 6 · near-miss · Same vendor, also MCP, but not Meko
**Input:** You want an agent to answer "what's our p99 order latency by region?" against your app's YugabyteDB.
```text
Option A: Meko                  → memory_search / knowledgebase_search
Option B: yugabytedb-mcp-server → SQL over your own cluster (tool names unverified)
```
**Output:** Meko has no SQL tool for your schema. Its MCP surface covers only conversations, memory, the knowledge base, datapacks, and artifacts. YugabyteDB runs underneath, but Meko doesn't expose it to you as a database.
**Signal:** Meko is memory for agents, not a database for agents to query. It decides what gets stored and who can see it, and it hides the storage engine.

## Pattern
- The **datapack** is the core primitive. It holds conversations, memories, knowledge documents, traces, and artifacts. Pass its ID explicitly on every call.
- Identity comes from the **API key**, which decides the user account. `agent_id` attributes writes, and it also gates edits to a memory.
- Memories are **private by default**. Promotion is the only way to share one, it is one-way, it needs an owner or maintainer, and it usually goes through human review.
- **Writes are curated:** conversations are extracted asynchronously and lossily, while `memory_add` is exact. **Reads go through ranked search**, not scans.
- **Traces record why.** Reasoning and plan travel with the output, so the next agent or an auditor gets the rationale too.
